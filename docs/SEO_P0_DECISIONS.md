# فاز P0 سئو: مدل گزینه‌ها — تصمیم‌ها و نکته‌ها

مرجع: `SEO.md` §۴.۳، §۴.۴، §۱۲.

## مدل داده

- `ProductOption` (گروه) ← `ProductOptionValue` (مقدار: `label`, `code`, `isActive`) و `VariantOptionValue` (پیوند ترکیب↔مقدار).
- هر ترکیب = یک `ProductVariant` با `optionKey`: کدهای گروه به‌ترتیب الفبا، مثل `fill:filled|valve:persi`. محصول بدون گزینه دقیقاً یک ترکیب `default` دارد؛ یکتا روی `(productId, optionKey)`.
- `unit`/`unitValue` اختیاری شدند؛ محصولات قدیمی با چند ترکیب کلید `legacy:{unitValue}` گرفتند (مایگریشن داده‌ی `20261001090000_seo_p0_options`) و همچنان قابل ویرایش‌اند، ولی ترکیب جدید فقط از طریق گروه‌های گزینه ساخته می‌شود.
- `Product.priceUpdatedAt` فقط با تغییر قیمت ترکیب به‌روز می‌شود؛ `Product.pairedProductId` دوطرفه است (جفت‌کردن، جفت قبلیِ هر دو طرف را آزاد می‌کند).
- `Category.h1`، `OrderItem.optionsSnapshot` (آرایه‌ی `{option, value}` هنگام ثبت سفارش)، `ShippingMethod.deliveryEstimate` و `businessHoursOnly`.

## قواعد

- مقدار گزینه هرگز فیزیکی حذف نمی‌شود (غیرفعال می‌شود)؛ پس از اولین سفارش، کد گروه/مقدار قفل است (برچسب و افزودن مقدار آزاد است).
- ترکیب بدون قیمت (`price = 0`) فقط غیرفعال می‌شود؛ هم اعتبارسنج ورودی و هم `changeVariantActive` فعال‌سازی‌اش را رد می‌کنند.
- «ساخت همه‌ی ترکیب‌ها» فقط ترکیب‌های ناموجود را (غیرفعال و بدون قیمت) اضافه می‌کند؛ تکراری نمی‌سازد.
- «محاسبه‌ی قیمت پرشده» = قیمت «خالی» + قیمت شارژ محصول متناظر؛ اگر قیمت‌های فعال شارژ یکسان نباشد، هشدار می‌دهد و پر نمی‌کند. یک‌بار پر می‌کند؛ پیوند دائمی قیمت‌ها نیست.
- «کپی محصول»: غیرفعال، نام «(کپی)»، نامک `-copy[-N]`، `focusKeyword` خالی، محصول متناظر کپی نمی‌شود، تصاویر با فایل جدید ذخیره می‌شوند.

## موارد باز برای الو کپسول

- «کپسول دست‌دوم» جفت شارژ ندارد؛ دکمه‌ی «محاسبه‌ی قیمت پرشده» برایش نمایش داده نمی‌شود و قیمت‌ها دستی وارد می‌شوند.
- مقدار `deliveryEstimate` و `businessHoursOnly` روش‌های ارسال را خود الو کپسول وارد کند (ادعایی ساخته نشده است).
